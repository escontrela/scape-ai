# SCAPE AI – Project Specifications

## Project Goal

Scape AI is a fully Java-based application designed to train an artificial intelligence agent capable of escaping 2D mazes through iterative learning. The system combines a graphical interface, a simulation engine, an AI learning model, and persistent storage of learned parameters.

The objective is to progressively improve the model so that, after many iterations, the agent can reliably solve complex mazes within a limited time.

The application must be implemented **entirely in Java**, using **Spring Boot** for the backend logic and **JavaFX** for the graphical interface.

---

# Core Concept

The application simulates an agent attempting to escape from a labyrinth.

Each run consists of:

1. Selecting a maze
2. Initializing the AI model
3. Running iterative movement decisions
4. Applying reinforcement feedback
5. Updating the model parameters
6. Persisting the updated parameters in the database

Over many iterations the model improves its ability to navigate efficiently.

# Main Components

## Maze Engine

Responsible for:

* Maze creation
* Maze loading
* Maze representation
* Collision detection
* Exit detection

Mazes are two-dimensional grids containing walls, empty spaces, a start position, and an exit.

The engine must support different maze sizes and complexity levels.

---

## Agent Simulation

The agent represents the entity trying to escape the maze.

Responsibilities:

* Maintain current position
* Maintain visited path
* Maintain movement history
* Provide context to the AI model

The agent moves step by step according to decisions generated by the AI.

---

## AI Engine

The AI component is responsible for generating the next movement decision based on the current context.

The system uses a transformer-style architecture that processes sequential context representing the exploration of the maze.

The model must learn patterns of movement and progressively improve through reinforcement signals.

The AI engine must support:

* Context ingestion
* Movement prediction
* Parameter updates
* Iterative training
* Model persistence

---

# Learning Model

The learning system is inspired by large language model architectures adapted for spatial reasoning.

At each step the model receives contextual information about:

* Current agent position
* Local maze environment
* Visited positions
* Previous movements
* Relative location of the exit

The model outputs a probability distribution over possible movement directions.

The system selects the most probable action or samples from the distribution.

---

# Reinforcement Feedback

The system uses reinforcement signals to guide learning.

## Positive Reinforcement

* Moving closer to the exit
* Discovering new cells
* Avoiding loops
* Reaching the exit

## Negative Reinforcement

* Hitting a wall
* Repeating previously visited paths
* Moving away from the exit

## Strong Negative Reinforcement

* Failing to escape within the time limit

The default time limit for a maze attempt is **5 minutes**.

---

# Training Process

Each training run may consist of thousands or millions of iterations.

During each iteration:

1. The agent receives contextual state
2. The model predicts the next action
3. The simulation executes the movement
4. The environment evaluates the result
5. Reinforcement feedback is generated
6. Model parameters are adjusted
7. Updated parameters are persisted

Training continues across application executions.

# Guardrails for AI Agents

## Spring Boot Constructor Injection

When a `@Component`, `@Service`, or `@Controller` class has **multiple constructors**, Spring cannot auto-detect which one to use for dependency injection. This causes the error:

```
No default constructor found
```

**Rules to follow:**

1. If a class has **exactly one constructor**, Spring uses it automatically — no annotation needed.
2. If a class has **two or more constructors** (e.g. a primary one for Spring and a package-private one for tests), you **must** annotate the Spring-facing constructor with `@Autowired`.
3. Never leave a multi-constructor `@Service` / `@Component` without `@Autowired` on the intended injection constructor.
4. After creating or modifying any Spring-managed bean, **verify** that the constructor Spring should use is unambiguous.
5. When adding a secondary constructor (for testing, defaults, etc.), always go back and add `@Autowired` to the primary constructor if it is not already present.
